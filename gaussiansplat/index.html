Plugin Details

Gaussian Splat Importer

Editor plugin for Unreal Engine 5.7 and newer. Imports, streams, edits, and renders 3D Gaussian splats in any compatible UE project — drop Plugins/GaussianSplatImporter into your game or tool project and enable the plugin. Supports local files (PLY / SPZ / SOG), native Virtual Page containers (.gsrad), optional World Labs Marble cloud generation, in-viewport Splat Edit tools, and 4DGS frame sequences with Sequencer integration.

Features

Core capabilities

  • GaussianSplatActor — level actor with UGaussianSplatRenderComponent, quality presets (Low → Ultra), optional Virtual Page manifest.
  • Automatic Virtual Page preparation — large imports (> threshold splats) build a SplatTree + .gsrad sidecar for disk streaming.
  • Hardware-aware budgets — RAM/VRAM reserves, GPU pool auto-sizing, TDR-safe processing caps.
  • Occlusion culling — splats behind opaque UE geometry rejected before sort/draw (configurable bias).
  • Live stats overlay — resident splat count, Virtual Page scheduler metrics, sort mode.
  • Color grading — per-actor tone mapping, exposure, tint, temperature, saturation (SuperSplat-like; applied in splat pixel shader).
  • Custom GPU renderer — instanced splats via view extension (radix sort, frustum cull, baked SH view color).
  • Sequencer — UMovieSceneGaussianSplatTrack drives 4DGS component time.

Not supported (v1)

  • Single-file .sog4d / TRBF checkpoint import
  • Save As on Virtual Page / streaming-only actors (splats not fully in RAM)
  • 4DGS sequence export from editor

Get Started

Installation & first scene

  1. Copy Plugins/GaussianSplatImporter into your UE project (or install from marketplace/Fab when published).
  2. Enable plugin Gaussian Splat Importer in your .uproject (Niagara is not required).
  3. Rebuild the editor target after C++ changes, e.g. Build.bat YourProjectEditor Win64 Development -Project="YourProject.uproject".
  4. Open Project Settings → Plugins → Gaussian Splat Importer.
  5. Set Virtual Page Profile to Auto (Recommended) — or pick a tier matching your GPU.
  6. For World Labs cloud generation, enter your WLT-Api-Key.
  7. Open Tools → Gaussian Splat Importer → Import File and choose .ply, .spz, or .sog.
  8. Select the spawned GaussianSplatActor in Outliner; press F to frame the camera.
  9. Adjust look under Details → Gaussian Splat → Color Grading (tone map, exposure, tint).
  10. For editing: Tools → Edit Gaussian Splats, select splats, use toolbar tools.

Renderer

Viewport drawing is handled by FGaussianSplatViewExtension and GaussianSplatActor — no third-party renderer plugins or manual content assets required.

After C++ or shader changes: full editor rebuild + restart (not Live Coding only). Hot-reload leaves stale DLLs and missing log lines.
New project / plugin-only copy: enable VSync in the host project ini if you see a horizontal seam while panning — see FAQ → viewport tearing. Plugin defaults do not set r.VSyncEditor.

GSPL v3 virtual page payload

Large scenes use quantized page bytes (position uint16, packed scales/rotations, optional proxy pages). Proxy spatial sampling picks the most significant splats per 3D grid cell instead of uniform decimation.

Virtual Pages

SplatTree streaming

Virtual Pages let city-scale scenes (10M–100M+ splats) render from disk without loading everything into RAM or VRAM.

Data model

  • SplatTree — hierarchical nodes with geometric error; each node has a proxy page (coarse) and optional leaf pages (full detail).
  • .gsrad file — binary page store (up to 64K splats per page, ~80 bytes/splat GPU pack).
  • Manifest asset — bounds, page directory, tree nodes, version metadata.

Runtime behavior

  1. Camera position + velocity drive visible cut selection (projected error threshold).
  2. Missing pages are read asynchronously from disk (MaxInFlightReadMB cap).
  3. Decoded pages upload to a fixed GPU page pool (auto-sized from VRAM fraction).
  4. Eviction reuses pool slots; ProxyRetainFrames protects fresh proxy from immediate eviction.
  5. Only active pages participate in depth sort and draw — typically 1–4M splats visible, not the full scene count.

Why VRAM stays ~3–5 GB on a 12 GB GPU

This is by design. The profile reserves VRAM for UE rendering, then allocates a fraction (e.g. 25–30%) to the splat page pool. The rest of the scene lives on disk and in CPU RAM cache. Task Manager Dedicated GPU Memory will not show 12 GB filled unless you force Custom settings with very high pool fraction (risk of OOM).

Debug overlay

Enable Virtual Page Debug Overlay in Project Settings. Shows activePages, activeSplats, poolPages, upload/read counters. Log line:

LogGaussianSplatImporter: Virtual Pages GPU publish: activePages=N activeSplats=M poolPages=P ...

Build Virtual Pages (manual)

Automatic preparation runs when splat count exceeds Auto Prepare Threshold (default 5M). For manual rebuild: use actor Details or importer pipeline after large PLY import.

GPU Rendering

Render pipeline

  • Instanced quads per splat — vertex shader projects 3D Gaussian to screen-space ellipse.
  • Radix sort back-to-front per view (r.GaussianSplat.SortMode).
  • Frustum + screen-radius cull before sort (gs.FrustumCullRadiusScale).
  • SH view-dependent color optional (gs.Render.UseSHViewColor).
  • Opaque occlusion — samples scene depth to drop splats behind UE meshes.
  • Cluster LOD path (optional Nanite-style clusters) for non-virtual static scenes.

Per-actor quality (EGaussianSplatQuality)

Color & tone mapping

Color look is not in Project Settings — it lives on each GaussianSplatActor → Gaussian Splat Render component.

Where: select the actor → Details → category Gaussian Splat → expand Color Grading.

Quality & Performance

SuperSplat parity & editor tuning (2026)

Recent renderer changes align color, transparency sort, mesh masking, and fill-rate cost with the SuperSplat / PlayCanvas reference. Defaults live in Plugins/GaussianSplatImporter/Config/DefaultEngine.ini under [SystemSettings].

Recommended editor setup

SettingValueWhy
Anti-AliasingFXAA (Project Settings → Rendering → Default Settings)TSR adds ~90 ms on splat-heavy views and causes mesh/splat boundary crawl. FXAA is stable and matches SuperSplat (no temporal jitter).
Screen Percentage100% (viewport toolbar, not 0.76×)Lower SP scales the whole frame down then upscales — splats look softer than SuperSplat at 100% canvas.
r.GaussianSplat.CompositeAfterTonemap1Splat color grading runs once (SuperSplat linear tonemap), not double-processed by UE ACES.
r.GaussianSplat.SortDepthMode0Sort by splat center depth. Legacy mode 1 (far edge) causes close-range dark spots on flat surfaces.
r.GaussianSplat.MinPixelSizeMode1Clamp + fade sub-pixel splats (PlayCanvas antialiased). Mode 0 hard-rejects them → speckle on walls/sofa.
r.GaussianSplat.AntialiasOpacity1Dim splats inflated by 0.3 px covariance dilation — removes residual dark speckle.
gs.Lighting.EnableAdditive0Keeps post-tonemap color path; additive relight is expensive and re-tonemaps splats.

Performance levers (after quality is correct)

Use stat GPU in the editor. Splat passes appear as:

  • GaussianSplatPrepare — decode, frustum cull, radix sort
  • GaussianSplatRaster — instanced draw + alpha blend (usually the bottleneck)
  • GaussianSplatComposite — splat layer → scene color

On a ~2M splat interior, typical split after FXAA + 100% SP: Prepare ~14 ms, Raster ~24 ms, Composite <1 ms. TSR alone can add ~90 ms — disable it before tuning splat CVars.

CVarSuggested testEffectLimitation
r.GaussianSplat.RenderScale0.7Raster splat layer at 70% res, bilinear upscale in composite. ~40% raster savings at 0.7, ~75% at 0.5.Range 0.25–1. Only applies when CompositeAfterTonemap=1. Slight softness on splats; mesh stays full res.
r.GaussianSplat.SplatLayer8Bit1 (default)8-bit RGBA splat layer after tonemap — half blend bandwidth vs float16.Display-referred [0,1] only; set 0 if banding in dark gradients.
r.GaussianSplat.MinPixelSize2.0SuperSplat minPixelSize — drops/zoom-out culling for tiny footprints.With MinPixelSizeMode=0, can expose dark under-splat speckle. Use mode 1.
r.GaussianSplat.SortEveryNthFrame2–4Skip sort on some frames.Visible lag / wrong order at edges when camera moves; use only to measure sort cost.

Character / mesh masking

Splats behind opaque UE geometry are rejected via scene depth. Fixes applied for editor viewport resize, fullscreen, and TAA jitter:

  • Depth lookup remaps raster pixels into the SceneDepth grid (GSplatOpaqueDepthUV) — pass-independent.
  • r.GaussianSplat.OpaqueDepthJitterScale — compensates TAA jitter on depth sample (1 = default, 0 = off if using FXAA).
  • r.GaussianSplat.OpaqueDepthFeatherPx — 2×2 sub-pixel depth gather at mesh boundary (0.35 default). 0 = hard cut.
Do not use TSR on splat + skeletal-mesh scenes if you see crawling edges or white fringe bands. Switch to FXAA first, then tune OpaqueDepthJitterScale only if needed.

Close-range “dirt spots” (fixed)

Dark noise on orange walls / sofa at close range, fading when zooming out or changing angle, was not SH bands, lighting, or virtual-page LOD. Root cause: depth sort key used the far edge of each Gaussian ellipsoid instead of its center. Elongated dark splats sorted on top of neighbours.

Fix: r.GaussianSplat.SortDepthMode 0 (default in plugin ini). Legacy reproduction: set to 1.

Profiling notes

  • stat GPU — use GaussianSplat* lines above; ProfileGPU often shows 0 ms for RDG passes on D3D12 editor.
  • Lighting/shadow CVars (gs.Lighting.*) have negligible cost when EnableAdditive=0.
  • Full resident scenes (1.92M splats in RAM, no Virtual Pages) ignore gs.VirtualPages.* budget CVars.

Virtual Page Profiles

Hardware presets

Profile names describe a target machine class (RAM + GPU tier), not how many gigabytes of VRAM splats will occupy. On a 12 GB card, splat VRAM is typically ~3–5 GB because the preset reserves VRAM for UE and only allocates a fraction to the page pool. The rest of a Virtual Page scene stays on disk and in CPU RAM cache.

Auto (Recommended) buckets detected RAM/VRAM and picks one row from the full table below. Custom exposes every field in Project Settings. Values are applied as CVars at module init (gs.VirtualPages.*, gs.Budget.*).

FAQ & Troubleshooting

Common issues

Black viewport / Splats: 0 with Virtual Pages

Cut stuck on root proxy only. Check log for activePages=1 activeSplats=8192. Fix: use Auto or a lower profile; restart editor after DLL rebuild; verify poolPages ≥ 64.

Low VRAM usage on high preset

Expected for streaming. Only visible pages occupy VRAM (~3–5 GB on 12 GB cards). Full scene is on disk. Pick profile matching your GPU, not Maximum · 32 GB GPU on a 12 GB card.

Build failed: Live Coding active

Close editor or press Ctrl+Alt+F11 before Build.bat.

Save As greyed out

Actor must have splats in RAM. Virtual Page streaming actors cannot Save As until edited splats are materialized.

Export / import orientation wrong

PLY uses mirror −1 X vs UE coordinates. Plugin applies consistent transform on import/export.

4DGS flicker between frames

Convert sequence with 4DGS → SOG for shared Morton order; enable Frame Blend + .gsorder sidecar.

Performance: sort lag on yaw

Try r.GaussianSplat.SortEveryNthFrame=2 or lower actor quality preset; for VP scenes ensure prefetch is not thrashing pool (PrefetchMaxPages).

Low FPS (~8) with 2M splats — TSR is the culprit

Run stat GPU. If TemporalSuperResolution is ~90 ms, switch to FXAA (r.AntiAliasingMethod 2) and set screen percentage to 100%. Splat raster is typically ~20–40 ms after that; tune r.GaussianSplat.RenderScale 0.7 if needed.

Dark spots / noise on walls and sofa at close range

Set r.GaussianSplat.SortDepthMode 0 (center sort). Legacy mode 1 sorts by ellipsoid far edge and pops dark splats on top. Not related to SH bands or lighting.

Flickering mesh outline / white fringe around character

Use FXAA instead of TSR. If persisting, tune r.GaussianSplat.OpaqueDepthJitterScale (0 with FXAA) and OpaqueDepthFeatherPx (0.35).

Splat mask shifts after fullscreen or brightness change

Ensure r.GaussianSplat.CompositeAfterTonemap=1 (depth remaps in shader). Do not mix BeforeDOF splats with post-tonemap color grading.

Directional shadow only on floor / grazing angles

Set gs.Lighting.ReceiveShadowsOnAllSplats 1.

Colors too dark or double-tonemapped

CompositeAfterTonemap=1, gs.Lighting.EnableAdditive=0. Adjust per-actor Exposure in Color Grading, not UE post-process alone.

Blurrier than SuperSplat reference

Check viewport screen percentage (must be 100%), RenderScale=1, and FXAA vs TSR. SuperSplat renders at native canvas resolution with no upscaler.

Horizontal seam / “layer” while panning (not a splat bug)

Symptoms: while rotating or moving the camera, part of the image looks like it slides opposite the motion (rolling-shutter-like); the effect grows with pan speed and disappears when you stop. Phone photos may show it; OBS and print-screen often do not — they capture a full finished frame, not the live scan-out on the monitor.

Cause: classic screen tearing when vertical sync is off. In the editor and Standalone Game, the critical CVar is often r.VSyncEditor (separate from packaged r.VSync / bUseVSync). This is not splat depth sort, composite misalignment, or Virtual Page streaming.

Fix:

  • Console: r.VSyncEditor 1, r.VSync 1; cap FPS to monitor refresh (t.MaxFPS 60 or Game User Settings → VSync + frame limit).
  • Persist in project Config/DefaultEngine.ini — [SystemSettingsEditor] with r.VSyncEditor=1 (see Project Settings → Display sync).
  • If it still tears, check Saved/Config/WindowsEditor/EditorSettings.ini for r.VSyncEditor=False and set it to True, then restart the editor.

Clean project note: copying only Plugins/GaussianSplatImporter does not copy host-project VSync ini — add the blocks above or expect tearing until VSync is enabled.
